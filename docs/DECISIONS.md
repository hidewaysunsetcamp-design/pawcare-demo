# 設計判断の記録（ADR）

PAWCARE デモ版の主な設計判断を短く残します。状態は「採用」「見送り」「置き換え」のいずれか。
判断を変えるときは、既存の記録を書き換えず、新しい番号で追加して元の記録を「置き換え」にしてください。

## ADR-001 GitHub Pages の静的サイトとして公開する

- **状態**: 採用（v1.0）
- **背景**: デモ段階で、運用費・サーバー保守・個人情報を預かる責任を最小にしたい。iPhone / Android の両方でインストール不要で使いたい。
- **決定**: HTML + CSS + JavaScript のみ（ビルド不要）で作り、GitHub Pages（`main` ブランチのルート）で配信する。PWA としてホーム画面追加・オフライン表示に対応する。外部ライブラリは原則使わず、必要なものは `js/vendor/` に同梱する（現在は QR コード生成のみ）。
- **結果**: 無料・高速に公開できる。一方で、サーバー側処理（ログイン、通知送信、データ保管、共有リンクの無効化）はできない。以降の ADR はこの制約を前提にしている。
- **関連**: README「障害記録と再発防止」（Web エディタ経由の編集で index.html が壊れた件。Git で直接コミットし `tests/verify.sh` で検査する）

## ADR-002 データは端末の localStorage に保存する

- **状態**: 採用（v1.0）
- **背景**: サーバーがないため、データは端末内に置くしかない。記録量は小さい（テキスト中心）。
- **決定**: キー `pawcare.v1` に JSON 1件で保存する。保存はすべて `commit()` 経由とし、失敗（容量不足・プライベートモード）したら変更前に戻してエラーを表示する。JSON バックアップ／復元を用意する。
- **結果**: 実装が単純でオフラインでも動く。代わりに、端末間で同期されない／iPhone では Safari とホーム画面アプリで保存先が別／ブラウザのデータ消去や iOS の長期未使用データ削除で消える、という制限がある。UI とガイドで明示し、バックアップを勧める。

## ADR-003 クラウド同期・ログインは当面見送る

- **状態**: 見送り（2026-11-18 オーナー判断）
- **背景**: 家族共有や機種変更への対応にはクラウド同期が有効。一方で、ペットの健康情報と飼い主の個人情報を預かることになり、認証・保管・漏えい対策・規約整備・運用費が必要になる。
- **決定**: v1.1.0 ではログインなし・クラウドなしを維持する。リマインダーと病院への共有は、サーバーを使わない方法（ADR-004、ADR-005）で実現する。
- **結果**: 運用負担と情報管理リスクを持たずに機能を増やせた。家族共有・端末間同期・アプリからのプッシュ通知はできないまま。再検討時は README「将来のクラウド化の提案」を出発点にする（`pets` / `logs` / `memos` / `reminders` はそのままテーブル化できる構造）。

## ADR-004 リマインダーの通知はスマホのカレンダーに任せる

- **状態**: 採用（v1.1.0）
- **背景**: Web Push はサーバーからの送信が必要で、iOS ではホーム画面追加が前提になるなど条件が多い。ADR-001・003 によりサーバーはない。
- **決定**: 予定はアプリ内に保存し、通知が必要な予定は利用者が「カレンダーに登録」する。.ics（予定時刻の VALARM、ワクチン・健康診断は前日にも VALARM、くり返しは RRULE）を生成し、iPhone は `data:text/calendar` URL で開いて「カレンダーに追加」画面へ、その他は .ics をダウンロード。Google カレンダーの予定作成リンクも用意する。
- **結果**: アプリを閉じていても OS 標準のカレンダー通知が届く。代わりに一方向の書き出しなので、アプリで予定を編集・完了・削除してもカレンダー側は更新されない（画面とガイドで手動更新を案内）。くり返し予定の「完了」で次回に進むのはアプリ内だけ。

## ADR-005 病院への共有は URL のフラグメントにデータを入れる

- **状態**: 採用（v1.1.0）
- **背景**: 受診時に、プロフィール・問診メモ・最近の記録を病院に見せたい。サーバーにデータを預けずに実現したい。病院側にアプリやログインを求めたくない。
- **決定**: 共有する情報を JSON にし、gzip（CompressionStream）＋ base64url で `#/view/<データ>` に入れたリンクを作る（未対応ブラウザでは非圧縮の `j` 形式）。`#` 以降はブラウザからサーバーへ送られないため、GitHub Pages のアクセスログにも残らない。病院側は同じアプリの `#/view/` 画面で「受診用サマリー」を閲覧専用・印刷可能な形で表示する。URL が 1800 文字以下なら QR コードも表示する。有効期限は作成時に埋め込み、閲覧側で判定する。
- **結果**: サーバー不要・病院側の準備不要で共有できる。代わりに、
  - リンクを知っていれば誰でも読める（病院以外に送らないよう画面で注意）
  - 送ったリンクは取り消せない。有効期限は表示上の目安で、強制力はない
  - 記録が多いと URL が長くなり QR コードが作れない（記録は最大120件・メモ200文字に制限）
  - 将来クラウド化する場合は、サーバー保管・失効可能なリンクへの置き換えを検討する

## ADR-006 診断・緊急度の判定はしない

- **状態**: 採用（v1.0〜）
- **背景**: 旧版は独自ロジックで緊急度を判定していたが、獣医師の監修がなく、誤った安心・不安を与える医療安全上のリスクがあった。
- **決定**: アプリは記録と情報整理に限定し、病名の推定・治療方針・緊急度の判定を表示しない。危険な兆候は「問診を待たず動物病院へ連絡する目安」として一覧を示すだけにし、該当する回答があれば病院への連絡を案内する。共有画面にも「飼い主が入力した情報で、診断や医学的な判断を含まない」と明記する。
- **結果**: 医療安全の条件を満たし、法的リスクを下げられる。AI 問診補助などを検討する際は、獣医師の監修と法務確認を前提とする。

## ADR-007 サービスの軸：「判断は獣医師に、準備は PAWCARE に」（2026-11-18）

- **状態**: 採用（オーナー決定）
- **決定**: PAWCARE は「獣医師の負担を減らす」と「飼い主の不安を減らす」の2つの役割を担う。病名・治療は獣医師が伝え、アプリは次の行動と情報の準備・橋渡しを受け持つ。
- **2つがぶつかるとき**: 場面で分ける。家で見る画面は飼い主を優先し、病院に渡すもの（受診用サマリー等）は獣医師を優先して短く要点だけにする。
- **測り方**: 獣医師の負担は、協力獣医師に模擬症例のサマリーあり／なしを読み比べてもらって測る（約45分×1回）。
- **「今すること」画面**（今すぐ電話／今日中に相談／記録して次回伝える）: 作るのは今から、公開は協力獣医師の監修後。

## ADR-008 病名・治療の伝達は協力獣医師のオンライン相談と連携する（2026-11-18）

- **状態**: 採用（方向性）。先生と運用を相談しながら試作する
- **決定**: 飼い主の記録・問診 → 協力獣医師 → 先生からの返事を飼い主に届ける流れを作る。獣医師向けAIは先生の下書き役（候補と根拠論文を出し、先生が確認・修正して送る）。
- **根拠**: 獣医師法第17条（獣医師以外の診療の業務化の禁止）。農林水産省「愛玩動物におけるオンライン診療の適切な実施に関する指針」（令和6年12月）。オンライン診療の実施条件・責任は獣医師側にある。
- **未確認**: 指針本文の詳細条件、「健康相談」と「診療」の境界 → 公開前に農林水産省窓口または弁護士に確認。

## ADR-009 生涯の「健康手帳」はまず飼い主の手元に置く（2026-11-18）

- **状態**: 採用（第1段階）。第2段階（クラウド）は未決定
- **決定**: マイナンバーのように病院をまたいで医療記録を持ち運べることを目指す。第1段階はサーバーなしで、もしもカード・受診の記録・処方・体重の推移・ワクチン/予防の記録を1冊にまとめ、PDF（印刷）と「手帳ファイル」（JSON・ペット1頭分）で持ち運ぶ。取り込み時は既存の記録を消さず、同じIDは追加しない。
- **第2段階の構想**: マイクロチップ番号をつなぎの番号にし、飼い主が許可した病院だけが読み書きできるクラウドの記録。ログイン・同意管理・病院側の入力画面・法的確認が必要で、ADR-003（クラウド見送り）の見直しを伴う。国のマイクロチップ登録制度（登録されるのは所有者情報）と連携しているように見せない。
- **判断材料**: 外平先生に「病院を変えたとき、この手帳が届いたら助かるか」を確認する。

## ADR-010 EXP・レベル・勲章は「飼い主の行動」だけに付ける（2026-11-18）

- **状態**: 採用
- **決定**: 記録を続けてもらい、正確なデータを増やすためにEXP・レベル・勲章を入れる。点数を付けるのは飼い主の行動（記録した日数、1日に複数種類の記録、メモつきの記録、週1回の体重、服薬・予防の実施、受診の記録、問診メモ、もしもカード、病院の電話番号の登録）だけ。
- **しないこと**: ペットの健康や食事への点数、他の子との比較・ランキング、記録の件数で増えるEXP（適当な記録の連打を防ぎ、データの質を守る）。画面に「ペットの健康状態を評価するものではありません」と明記。
- **AI学習への利用（将来）**: 記録は端末内だけにあり、AIの学習には使っていない。使う場合はクラウド化（ADR-003の見直し）と、飼い主の明示的な同意・匿名化・利用目的の説明が前提。

## ADR-011 競合との戦い方：「受診の瞬間」を取り、資金のある相手と正面から戦わない（2026-11-19）

- **状態**: 採用（オーナー決定）
- **主戦場**: 受診の瞬間（病院に電話する・受付に立つとき）。電話の読み上げメモ、病院の登録不要のQR要点、健康手帳を磨く。
- **戦わない**: 見守りデバイス（Catlog・PetVoice）、予約・会計の病院向けSaaS（PawReco等）、AIによる診断、24時間の獣医師相談。デバイスや病院向けの仕組みとは、記録や要点を渡し合う相手として組む。
- **堀**: 獣医師からの信頼（監修・「判断は獣医師に」）、病院からの紹介で広がる流れ、同意を得た長期の記録。
- **料金**: 命に関わる機能（緊急時の案内・記録・病院に渡す要点）はずっと無料。値下げ競争はしない。
- **最初の利用者**: 外平先生の病院の飼い主（先生から勧めてもらう）。HIDEAWAYはペットと関係のない店のため販路にしない。
- **弱点**: 家族との共有。試用で不満が多ければクラウド化（ADR-003の見直し）で追いつく。

## ADR-012 料金プランと収益源（2026-11-19）

- **状態**: 採用（オーナー決定）。課金の仕組みはクラウド化のあとに実装
- **プラン**:
  - 無料：記録・緊急時の案内・病院に渡すQRの要点・もしもカード・問診メモ・ごはんチェック（計算）・健康手帳（直近3か月）。命に関わる機能は無料のまま（ADR-011）
  - プロ 月480円（年4,800円）：AIの栄養管理（写真で成分の読み取りは月30回まで・体重目標の見守り・補える食品タイプ）、AIの問診補助、月1回の振り返りレポート（診断はしない）、健康手帳のフル版、広告なし
  - ファミリー 月780円（年7,800円）：プロの内容＋家族4人で共有（自動同期・服薬の担当・お知らせ）、広告なし
- **プラン以外の収益源**: 首輪用QRタグ（実物）、健康手帳の製本版、病院向け（将来・外平先生の意見のあと）
- **広告（ADR-011の一部を見直し）**: 無料プランに限り、フードなどの広告を載せる。プロ・ファミリーは広告なし。広告の収益はAPI代に回す。
  - 守ること：必ず「PR」と表示する（景品表示法のステルスマーケティング規制）。緊急時の案内・問診・病院に渡す要点・ごはんチェックとAIの結果の中には出さない。AIの提案と広告を結びつけない。追跡用の外部スクリプトは使わない。

## ADR-013 対応する動物を10種類に広げ、飼い方のめやすを入れる（2026-11-19）
- 背景：ペットノートPlusは犬・猫以外の動物も記録できる。PAWCAREも同じ範囲で使えるようにしないと比較で負ける。
- 決定：犬・猫・うさぎ・ハムスター・インコ/文鳥・爬虫類・魚・リス・昆虫・その他の10種類にする。ワンタップ記録は動物ごとに並びを変える（爬虫類：脱皮・温度、魚：水換えなど）。体重は小数3桁（g単位の小動物向け）。
- 飼い方のめやす（#/guide）：動物ごとの温度・湿度・ごはん・寝床・習性・歴史と、全品種の由来・歴史・気をつけたいことを js/care.js に持つ。獣医師の監修は準備中と明記し、体調の判断には使わせない。
- 医療の案内は犬・猫向けのまま広げない：危険な兆候の一覧とごはんチェックは「犬・猫を中心にした目安」と明記。ほかの動物には「小さな変化でも、診られる動物病院に早めに相談」と、診られる病院の検索リンクだけを出す。
- 法令に関わる記載（アカミミガメの条件付特定外来生物、プレーリードッグの輸入禁止、ワシントン条約など）は監修時に再確認する。

## ADR-014 「うちの子」アバターとWiiに学ぶホーム、ペットノートPlusへの上塗り戦略（2026-11-19）
- 背景：ペットノートPlus（★4.6・6,883件）と記録の機能はほぼ同じ。広まる差は「SNSで自慢したくなるフック」。オーナー判断：危機感を持って、同じ機能を入れたうえで上塗りして勝つ。
- 決定（v1.11）：
  - ホームに、選んだ動物の丸いゆるキャラ風アバター（10種類すべて、SVG）。着せかえ＝からだの色14・もよう5・おめめ4・アクセサリー7・はいけい5。設定値は一覧のidだけ保存し、一覧にない値は既定値に戻す。
  - しゃべりかけ：記録の状況から決まったセリフを選ぶ（AIは使わない・無料）。記録をうながす／ほめる／予定・もしもの準備を思い出させるだけで、病気の判断や「大丈夫」は言わない。危険の案内が出ている間は動きを止め、「上の案内を先に見てね」だけにする。
  - じまん画像（1080×1350）：アバター・名前・レベル・連続記録日数だけ。健康の記録は入れない。端末の共有メニュー（なければ保存）でSNSへ。
  - 画面：Wiiの「白とうすい空色・大きく丸いボタン・文字が少ない・押すと反応する」という考え方を参考にする。任天堂の画像・キャラクター（Miiなど）・ロゴ・効果音は使わない。まずホームと着せかえだけ変え、オーナーの確認後にほかの画面へ広げる。
- ペットノートPlusに対して、まだ足りないもの（次に入れる候補）：写真つき記録、費用の管理、体温の記録、最大15人のリアルタイム共有（＝クラウドが必要。ADR-003の見直しと費用の確認が前提）。
- 上塗り（PAWCAREにしかないもの）：病院に渡すQRの要点、もしもカード、問診メモ、誤食の記録→電話、家族への引き継ぎ、飼い方のめやす、アバターとじまん画像。
- Catlog（RABO）との連携は将来の提携案件。首輪・トイレの自動記録をPAWCAREの受診用の要点にまとめられれば価値が大きいが、公開の連携方法は確認できていないので、提携の相談から始める。

## ADR-015 アバターをオーナー提供のイラストに差し替え、動きと手応えを入れる（2026-11-19）
- アバター：オーナーが用意したイラスト10種類＋すがた違い5種（img/avatars/*.webp、背景を透明にして切り出し）。着せかえは「すがた・アクセサリー（リボン・パーティー帽・おうかん）とその色・はいけい」。色やもようは絵に描かれているため変えない。
- 動き（「AIでアプリを作る時に使う、動きの名前24」から、使える所だけ）：リップル、トグル、ローディングボタン、スケルトン、プログレスバー、トースト、ボトムシート（ばね・下に引いて閉じる）、スワイプで削除（元に戻せる）、「＋1」のはじけ、紙吹雪（レベルアップ・勲章のときだけ）、シェイク、スタッガー。
- 入れなかったもの：プルトゥリフレッシュ（サーバーがない）、カルーセル・ドロワー・並べ替え・長押しメニュー・丸く広がる切り替え（今の画面に置き場所がない）、フローティングラベル（見出しが小さくなると高齢の方に読みにくい）、タイピングインジケーター（AI問診を入れるときに使う）。
- 守ること：緊急・問診・危険の案内中はお祝いや遅れて出る動きを使わない。端末の「動きを減らす」設定ではすべて止める。

## ADR-016 Duolingoに学ぶ「楽しく続く」しくみ（2026-11-19）
- 背景：オーナーがDuolingoの画面録画を共有。「楽しみながら続けやすい」しくみ、通知、正解時の振動、合間の動きを入れたい。
- 決定（v1.13）：
  - 今日のおせわ：動物ごとの毎日の目標（犬＝ごはん・飲水・散歩・排便・排尿、爬虫類＝温度・飲水など。毎日食べない爬虫類・昆虫はごはんを入れない）。太い進み具合バーと、ワンタップ記録のボタンに「✓／まだ」の印。
  - 全部できたら「パーフェクト！」のお祝い画面（XP・連続日数・パーフェクト回数、紙吹雪、振動）。XPは「今日のおせわパーフェクト」1頭1日ごとに＋20、勲章を2つ追加。点数をつけるのは飼い主の行動だけ（ADR-012の方針どおり）。
  - 2分以内に続けて記録すると「コンボ×n」。厚みのある押しボタン（押すと沈む）。
  - 通知：オーナー判断で、まず無料の方法。毎日の「記録の時間」をスマホのカレンダーに登録する（毎日くり返し・時刻にお知らせ）。アプリらしい通知は、クラウド化のときに通知用サーバーと合わせて検討する。
  - 振動はAndroidのみ（iPhoneのブラウザは振動に対応していない）。
- 守ること：危険の案内が出ているときは、パーフェクトのお祝いを出さない。飼い方クイズの道・もしもの練習は今回は見送り（もしもの練習は監修後）。

## ADR-017 Finch×Duolingo×Atoms：会いたくなるホーム、タップの瞬間の反応、今週のようす、音と振動（2026-11-19）
- ホーム（Finch）：上に大きなうちの子、すぐ下に「今日のお世話」の一覧（行をタップするとそのまま記録）。項目は飼い主が1〜6こ選べる（ブラッシングを新しく追加）。
- 反応（Duolingo）：記録した瞬間に✓、うちの子がぴょこっと跳ねて首をかしげ、項目ごとのひと言。短い効果音と軽い振動。全部そろったときだけ肉球スタンプでお祝い。
- 今週のようす（Atoms）：項目ごとに「今週の回数」「最後はいつか」「先週との差」と7日分の点。事実だけを出し、多い・少ないを病気の判断につなげない。
- サウンドデザイン：音源ファイルを使わず Web Audio で作る短い音（記録・コンボ・なでる・パーフェクト・まちがい）。ハプティクス：Androidは振動、iPhoneはiOS 18以降のスイッチ部品の手応えを使う。どちらも設定でオフにできる。

## ADR-018 外平先生のご意見を緊急時に反映（下書き）・レビューの指摘を反映・仕事の姿勢（2026-11-19）
- 外平先生（LINE、2026-11-19）：プレゼン資料とアプリは「とても見やすい」「まずはこれでやっていい」。緊急時に①イラストと食べてはいけないものリスト、②熱中症を含めて病院に連れて行くまでにできること、③特に心配な病気（犬のメスの子宮蓄膿症、猫の血栓症と尿閉、大型犬の胃拡張胃捻転）。

## ADR-020 サービス名を「ことぽすと」に（2026-11-19）
- 経緯：PAWCARE は国内外に似た名前が多い。オーナーと検討（LogMagic／Jpet Magic／ことづて／ことぽ）し、「ことづて」を抽象化した「ことぽすと」に決定。
- 意味：言葉にできないうちの子の「こと（言・事）」を入れておくと、先生へ届く「ぽすと」。呼び名は「ことぽ」。合言葉「うちの子の“いつも”を、先生へ。」
- 外した案：たより（PR TIMES の Tayori と重なる）、むすび（保護犬猫の OMUSUBI と重なる）、〜Magic（「勝手に分かる・AIが判断する」と受け取られるおそれ）。
- 変更（v1.16）：画面・アプリ名・ホーム画面の名前・共有文・じまん画像の文字を「ことぽすと」に。バックアップや健康手帳ファイルの形式名（app: "PAWCARE"）・保存場所・リポジトリ名は互換のため変えない（読み込みは両方受け付ける）。
- アドレスは kotopost.pet（ADR-019 を更新）。商標の確認は未実施（クラウドファンディング前に J-PlatPat で確認）。

- 追記（2026-11-19 17:00）：アドレスは .pet ではなく **kotopost.jp** を取得（初年度1円、更新3,124円/年、Whois公開代行あり・自動更新あり）。日本のサービスだと一目で分かるため .jp を採用。

## ADR-021 研究・開発への協力の同意を、先に入れておく（2026-11-26）
- 決めたこと：設定に「研究・開発への協力（任意）」を追加。最初はオフ。同意すると `settings.research = {agreed, at, v}` を端末に保存。説明文の版 `RESEARCH_TERMS_V`（いまは1）が変わったら同意は無効になり、取り直す。
- 理由：ログイン・クラウド保存ができてから全員に同意を取り直すのは難しい。先に「何に使い、何をしないか」を約束しておくと、利用者の安心にもなる（オーナー判断）。
- いまはデータを外に送らない。同意は「ログイン後に、匿名の形で研究・開発に使ってよい」という意思表示として保存するだけ。
- 約束：一頭ずつの記録・個人がわかる情報は、売らない・渡さない。外に出すのは集計した統計だけ。同意しなくても全機能を使える。いつでもやめられる。
- 次にやること：ログイン実装時、同意した人だけを集計の対象にする。利用規約・プライバシーポリシーに同じ内容を入れ、弁護士に確認してもらう（docs/legal/research-consent.md）。
