## まず結論（いちばん効くもの）
1. **パーフェクトの紙吹雪が、お祝い画面の「裏」に出ていて見えない**。閉じたあと別の画面に降ってくる（撮影で確認）。
2. **「どんっ」の音が、肉球スタンプが押される瞬間より約0.2秒早い**。音（650ms）と絵（865ms）がずれていて、決めの一発がぼやける。
3. **今日のお世話の行が、押すと1.12倍にふくらんで枠からはみ出す**。小さいボタン向けの動きを、横長の行にそのまま使っている。
4. **お世話の行を押すころには、うちの子が画面の外にいる**。最初の画面で見えるお世話は1行目の途中まで。跳ねる・首をかしげる反応がほとんど見られていない。
5. **記録するたびに、記録ずみの✓が全部いっしょに「ぽん」と跳ね直す**。新しく付いた✓が目立たない。進み具合バーも伸びる動きが出ていない（画面を作り直すため）。

## 1. 動き（モーション）

### A-1 紙吹雪をお祝い画面の前に出す【優先度A】
- 今：`.confetti { z-index: 70 }`、`.celebrate { z-index: 80 }` → 紙吹雪が裏に隠れる。お祝いを閉じても3秒消えないので、きせかえ画面などに降ってくる。
- 変更：`css/style.css` `.confetti` を `z-index: 85` に。`js/app.js` `celebratePerfect()` の `close` で `document.querySelectorAll('.confetti').forEach(e => e.remove())`。画面が切り替わったとき（hashchange）にもお祝い画面と紙吹雪を消す（今は `#/avatar` に移ってもお祝い画面が残ったまま。上の「緊急時」ボタンもその間かくれている）。
- 狙い・メリット：いちばん大きなごほうびが、ちゃんと見える。閉じたあとに関係ない画面で降る違和感がなくなる。
- 注意点・トレードオフ：紙吹雪が「つづける」ボタンに重なるが `pointer-events: none` なので押せる。粒の数は46→**32**に減らし、見た目の量はそのままで重さを抑える。

### A-2 スタンプの音・振動・絵を同じ瞬間にそろえる【優先度A】
- 今：スタンプは `animation: stamp .45s … .55s`。いちばん沈む70%の地点＝**865ms**。音と振動は `setTimeout(…, 650)`、紙吹雪は700ms。
- 変更（`js/app.js` `celebratePerfect()`）：音と振動 650→**860ms**、紙吹雪 700→**900ms**（押した直後に舞い上がる＝フォロースルー）。
- スタンプの動き（`css/style.css` `@keyframes stamp`）を「構え→押す→はね返り」に：
  `0% { transform: scale(2.4) rotate(-30deg); opacity: 0 } 55% { transform: scale(2.2) rotate(-26deg); opacity: .9 }`（空中で一瞬ためる）`72% { transform: scale(.86) rotate(-12deg); opacity: 1 }`（押す＝865ms付近）`86% { transform: scale(1.04) rotate(-15deg) } 100% { transform: scale(1) rotate(-14deg); opacity: .92 }`。長さ .45s→**.50s**、遅れ .55s→**.50s**、曲線 `cubic-bezier(.5, 0, .4, 1)`（ばねの行き過ぎはキーフレームで描く）。押す瞬間＝500+360＝**860ms**。
- 押した瞬間に `.cel-card` を 1 回だけ 3px 沈める（`translateY(3px)` を 80ms→戻り 120ms）。「ずしっ」とした手応え（ヒットストップの代わり）。
- 位置：今は「パーフェクト！」の「！」に重なって読めない。`.paw-stamp` を `right: -14px; top: -38px; width: 76px; height: 76px` に。
- 狙い・メリット：音・振動・絵が1点に集まり、短くても「決まった！」感が出る。
- 注意点：「動きを減らす」設定ではスタンプは最初から押された形で表示し、音・振動は **0ms**（すぐ）に出す。待たせる理由がないため。

### A-3 お世話の行は「ふくらむ」より「沈んで戻る」【優先度A】
- 今：`M.pop()` が `.care-row` にも `@keyframes pop`（1.12倍）を使う。幅306pxの行が約343pxになり、カードからはみ出して上下の行に重なる（40msの撮影で確認）。
- 変更：`css/style.css` に行専用を追加。
  `.care-row.popped { animation: row-pop .32s cubic-bezier(.3, 1.6, .5, 1); }`
  `@keyframes row-pop { 0% { transform: translateY(3px) scale(.985) } 45% { transform: translateY(-2px) scale(1.02) } 100% { transform: none } }`
  （押して沈んだ形から始まり、少し浮いて戻る＝指の「押した」とつながる）。`.quick-btn` の 1.12 はそのまま（小さいので気持ちいい）。
- 「＋1」：今は右上（`right: 8px; top: 6px`）で✓の丸に重なり、薄い緑で250msにはほぼ見えない。行のときは `right: 52px; top: 50%; margin-top: -12px; font-size: 1.15rem; color: #2f9e1f; text-shadow: 0 1px 0 #fff;`、動きは `plus-one` を **700ms**、`0% {translateY(4px) scale(.6); opacity:0} 20% {translateY(-4px) scale(1.15); opacity:1} 60% {translateY(-14px) scale(1); opacity:1} 100% {translateY(-24px); opacity:0}`（はじけて、少し見せてから消える）。
- 狙い・メリット：はみ出しがなくなり、上品なまま手応えが残る。数字が読める。
- 注意点：コンボの文字（「コンボ×3」）は長いので、行では `right: 52px` から左へのびる。

### A-4 ✓のぽんは「新しく付いた行だけ」、バーはちゃんと伸ばす【優先度A】
- 今：記録のたびに画面を作り直すため、記録ずみの✓すべてで `check-pop` が再生される（調べたら全部の✓で動いていた）。バーは新しい幅で作られるので `transition: width .6s` が効かず、伸びる動きがゼロ。
- 変更（`js/app.js`）：`quick` で記録した項目を `justDone = cat` に覚え、`careListHtml()` で該当行だけ `class="care-row done just"` を付ける。CSSは `.care-row.done .care-check` の animation を **`.care-row.just .care-check`** にだけ付ける。バーは前の幅 `prevPct` を `style="width:前%"` で描き、描いた直後（`requestAnimationFrame` 2回）に新しい幅を入れる。バーの曲線は今の `cubic-bezier(.2, 1.3, .4, 1)` .6s のままでよい。
- 同じ理由で `av-btn react` も「5秒以内に画面を作り直すと何度でも跳ね直す」。`avReact` は1回使ったら消す（`avReact.used = true`）。
- 狙い・メリット：「今押したもの」に目が行く。バーが伸びる＝「進んだ」がいちばん分かる絵になる。
- 注意点：「動きを減らす」設定ではバーは一瞬で変わる（今のまま）。

### B-1 うちの子のジャンプに「ため」と「着地」を入れる【優先度B】
- 今：`av-jump`（なでる）は 0%→40%で上がって戻るだけ、`av-react`（記録）は跳ねて傾くだけ。補間まかせで少し「ぬるい」。
- なでる（`css/style.css` `.av-btn.jump .av-body`）：長さ **.52s**、曲線 `linear`（キーフレームごとに指定）。
  `0% { transform: none; animation-timing-function: cubic-bezier(.3,0,.6,1) } 12% { transform: translateY(2px) scale(1.06,.92) }`（しゃがむ＝押した次のフレームから動く）`42% { transform: translateY(-22px) scale(.96,1.05); animation-timing-function: cubic-bezier(.4,0,1,1) }`（のびる）`70% { transform: translateY(0) scale(1.08,.93) }`（着地でつぶれる）`85% { transform: scale(.98,1.02) } 100% { transform: none }`
- 記録（`.av-btn.react .av-body`）：長さ .7s→**.9s**。`0% none / 10% translateY(2px) scale(1.05,.94) / 34% translateY(-16px) rotate(-4deg) scale(.97,1.04) / 52% translateY(0) scale(1.06,.95) / 64% rotate(6deg) / 88% rotate(6deg)`（首をかしげて**0.2秒止める**＝決めポーズ）`/ 100% none`。
- 吹き出しの文字が変わるとき `#avBubble` に 180ms の `scale(.94)→1` を足す（話しかけた感じ）。
- 狙い・メリット：押した直後の1コマ目から形が変わるので、反応が速く感じる。止めがあると「首をかしげた」が見える。
- 注意点：`transform-origin: 50% 95%`（足元）は今のまま。つぶれ方はイラストの輪郭が崩れない範囲（縦0.92まで）にとどめる。

### B-2 ボトムシート：行き過ぎで下にすき間が出る／閉じるときに動きがない【優先度B】
- 今：`sheet-up .38s cubic-bezier(.2, 1.25, .4, 1)` で、パネルの下端が画面の下から **12px 上がり**、すき間から後ろが見える（計測：下端652／画面664）。閉じると一瞬で消える。

- 狙い・メリット：出るときは軽く、閉じるときは「しまわれた」と分かる。
- 注意点：緊急時の画面から開くシートは、閉じる動きも **0ms**（すぐ消す）でよい。

### B-3 リップルは「スクロールのつもり」で出さない【優先度B】

### B-4 スタッガー（画面が出るときの時間差）を少し短く【優先度B】

## 2. 音（サウンド）
全体：今は音を直接スピーカーにつないでいる。**音の出口を1本にまとめ**（音量 0.8 ＋ 音割れ防止の圧縮 `DynamicsCompressor`：threshold −18dB、ratio 4、attack 3ms、release 120ms）、重なっても割れないようにする。立ち上がり（`tone()` の 12ms）は **5ms** に短くして「アタック強め」に。終わりは今の指数カーブでよい。

### A-5 「どんっ」がスマホのスピーカーでは聞こえない【優先度A】
- 今：`stamp` の一発目が三角波 180→90Hz。スマホの小さいスピーカーは約300Hzより下がほぼ鳴らないため、実際には「ドミソド」だけが聞こえる。
- 変更（`js/motion.js` `SOUNDS.stamp`）：
  - 当たり：**ノイズ 30ms**（バンドパス 1,200Hz、Q=1.2、音量 0.16、立ち上がり 2ms）＋ **sine 392→196Hz 110ms 音量 0.18**（聞こえる高さで「とんっ」）。
  - その後 120ms から **C6・E6・G6（1047/1319/1568Hz）を 70ms 間隔、各 160ms、音量 0.06**、最後に **C7 2093Hz を 380ms、音量 0.05**（キラッと余韻）。全体 約0.75秒。
- 狙い・メリット：スタンプの「押した」手応えがスマホでも届く。高い音を小さめにして耳に刺さらない。
- 注意点：1日1回だけの音なので少し派手でよい。マナーモードでは鳴らない（iPhoneの仕様）ことは設定画面の説明どおり。

### A-6 毎日何度も鳴る「記録」の音を、飽きない・疲れない形に【優先度A】
- 今：`tick` は sine 880→1320Hz・90ms・0.10。毎回まったく同じ。
- 変更：
  - `tick`：**sine 1175→1480Hz（40msで上がる）、長さ 70ms、音量 0.08** ＋ 頭に **triangle 2350Hz 12ms 音量 0.025**（「コッ」と指先に当たる感じ）。毎回 **高さを ±25セント（約±1.5%）ランダム**にずらす。
  - `combo`：続けた回数で高くする。2音（60ms間隔、各 70ms／110ms、音量 0.07）の基準を **988Hz × 2^(全音×(n−2)/6)**、上限 n=6（+8半音）。「ぴぽっ」が階段のように上がり、続けるほど気持ちいい。
- 狙い・メリット：1日に10〜20回鳴っても耳が疲れにくい。続ける楽しさが音で分かる。
- 注意点：音量は今より少し下げる。設定で切れることは今のまま。

### B-5 足りない音・あえて鳴らさない音【優先度B】
| できごと | 提案 | 値 |
|---|---|---|
| 取消・元に戻す（新規 `undo`） | 鳴らす（記録の逆向き） | sine 1320→880Hz、60ms、音量 0.05 |
| なでる（`tap`） | 今のまま＋連打対策 | sine 660→990Hz 60ms 0.06 のまま、高さ ±80セントでランダム、**120ms以内の連打は2回目から鳴らさない** |
| きせかえを選んだ | `tap` を使う | 上と同じ。B-6のうちの子の反応と同時 |
| シートを開く・閉じる | **鳴らさない** | 1日に何度もある、情報の操作なので静かに |
| 入力のまちがい（`error`） | **鳴らさない（振動だけ）** | 今もどこからも鳴らしていない。高齢の方を驚かせないため、この方針を ADR に明記 |
| 緊急時・問診・誤食・危険の案内 | **鳴らさない** | 今の実装（誤食は鳴らさない）を守る |
- もう1点：最初の音が鳴らない／遅れることがある（iPhoneは音の準備が初回タッチの中でしか始まらない）。`js/motion.js` で **最初の `pointerdown` で `ctx()` を作って `resume()`** しておく。

## 3. 振動（ハプティクス）
- Androidの多くの端末は **15ms より短い振動はほとんど感じない**。今の `light: 12`、`success: [14,50,14]`、`combo: [10,40,10,40,10]` は弱すぎるか、ぼやける。
- `js/motion.js` `PAT` の提案：

| できごと | 今 | 提案 | 意味 |
|---|---|---|---|
| なでる `light` | 12 | **15** | 「ぷに」1回 |
| 記録 `success` | [14,50,14] | **[20]** | 1回だけ。毎日何度もあるので短く1回 |
| コンボ `combo` | [10,40,10,40,10] | **[14,60,22]** | 2回目を強く＝「もう1つ」 |
| パーフェクト `stamp` | [30,60,30,60,120] | **[40,80,12,58,12,58,12,58,30]** | スタンプ（40ms）→ドミソドの音に合わせて3回コツコツ→最後の音 |
| まちがい `error` | [20,40,20] | **[30,70,30]** | 成功と区別できる「ブッブッ」。強すぎない |
| 取消 `undo`（新規） | なし | **[10]** | ごく軽く |

- iPhone（スイッチ部品の方法）：**指で押したその場でしか効かない可能性が高い**（タイマーで遅れて呼ぶと無反応のことがある）。パーフェクトの860ms後や70ms間隔の2回目以降は効かない前提で、iPhoneは「押した瞬間の1回」に絞る。パーフェクトは最後に押した瞬間に1回出しておく。→ **実機確認が必要**（iOS 18／26）。
- 注意点：振動は設定でオフにできる今の仕組みのまま。

### B-6 きせかえ画面：選んだら、うちの子が反応する／見本が見えなくならない【優先度B】
- 今：色やアクセサリーを押すと画面を作り直すだけで、うちの子は動かない（見本は `.av-live` でもない）。「はいけい」は下のほうにあり、選ぶころには見本が画面の外。

  - 見本（`.stage.small`）を `position: sticky; top: 56px; z-index: 5`、スクロールしたら **160→112px** に縮める（`transition: height .2s`）。
  - 選んだ瞬間に見本へ B-1 の「記録」の反応を **短く（.5s）** 再生＋`tap` の音＋振動15ms。背景を変えたときは背景色を **.3s** で切りかえる（今は一瞬）。

## 守ること（すべての提案に共通）
- 緊急時・問診・誤食・危険の案内中：お祝い・紙吹雪・効果音・遅れて出る動きは出さない（`homeDangerBanner` と `currentView` の判定は今のまま使う）。
- 端末の「動きを減らす」設定：新しく足す動き（`row-pop`・スタンプの沈み・きせかえの反応・シートを閉じる動き）も、すべて `@media (prefers-reduced-motion: reduce)` で止める。音と振動は動きとは別に、設定のオン・オフに従う。
- セリフや文字は記録をほめる・うながすだけ。病気の判断や「大丈夫」は書かない。
