## 1. 結論（3行）

1. 評価の高いサービスに共通するのは「**ワンタップ記録＋前回から何時間かが一目で分かる**」「**家族・預け先と引き継げる**」「**記録がそのまま先生への説明になる**」の3つ。一方、低評価は「**ログイン・機種変更でデータが消えた**」「AIの判定が当たらない」「課金・解約」に集中している。
2. PAWCARE の差別化点は「**電話で読み上げるメモ**」「**30秒で読める受診用サマリーを登録なしで病院に渡せる**」「**判定しない・ログインなし（消えない）**」で、調べた27件に同じ組み合わせはなかった。弱い点は「家族と共有できない」「前回からの時間・グラフがない」「受診後の記録（先生に言われたこと・処方）がない」。
3. 取り入れ案のトップ5はすべてサーバーなし・判定なしで作れる：①もしもカード（ペット版メディカルID）②前回から○時間の表示 ③誤食メモの項目化 ④受診記録と処方の服薬予定 ⑤家族への引き継ぎ（テキスト＋取り込みリンク）。

## 3. 評価されている点のパターン／不満が多い点

### 3-1. 評価されている点（複数のサービスに共通）

| パターン | どのサービスで評価されているか（レビュー・記事の内容を言い換え） | PAWCARE の今 |
|---|---|---|
| **P1 ワンタップ記録＋「前回から何時間」** | ぴよログ：各項目の最後の記録が何時間前か分かりやすいという声、片手操作（★4.8／約12万件）。Huckleberry：ワンタッチ記録（★4.9） | ワンタップ記録はある。**前回からの時間・今日の回数はホームに出ない** |
| **P2 家族・世話をする人と引き継げる** | ぴよログ：夫婦の共有が便利という声。Huckleberry：共有で世話の受け渡しがスムーズ。ペットノートPlus：15人共有。母子モ・EPARKお薬手帳：家族の一括管理が好評 | **できない**（ADR-003）。テキストで送る手段もまだない |
| **P3 記録がそのまま先生への説明になる** | Huckleberry：記録で医師の質問に答えやすい。Ubie：受診時に説明しやすいよう整理できる。Ada・Medisafe：医師に渡すレポート。11pets・CatsMe：受診時に記録を見せられる。アニカル：請求の履歴が通院記録の代わりになる | **強い**（要点→日ごとの要約→全記録、電話読み上げメモ、共有リンク/QR） |
| **P4 時間外に専門家につながる安心** | ペットドクター：かかりつけが閉まっている夜・週末に助かる。Airvet・Pawp：すぐつながる、不要な救急受診を避けられた。ペッツオーライ：24時間が初心者に心強い | 夜間病院の事前登録と電話ボタンまで。相談先そのものはない（ADR-008 で外平先生と試作中） |
| **P5 「次にすること」がボタンで出る** | Q助：結果から119番・医療機関検索・タクシーへ進める。Pet First Aid：救急病院の検索、緊急の項目が使いやすい。ASPCA：中毒相談にワンタッチ電話 | 緊急時画面の電話・地図はある。誤食の疑いから電話へ進める |
| **P6 予定が自動で計算され、確実に届く** | 母子モ：次の接種日の自動計算が便利。Medisafe：画面が消えていても鳴る通知が信頼されている | 予定・くり返しはある。通知はカレンダー任せ（ADR-004） |
| **P7 オフラインで見られる・緊急時にすぐ出る** | EPARKお薬手帳：オフライン閲覧が好評。メディカルID：ロック画面から医療情報を見せられる。ASPCA：オフラインで検索できる | PWAでオフライン表示可。ただし「1枚で見せるカード」はない |

### 3-2. 不満が多い点（PAWCARE が避けるべきこと／勝てるところ）

| 不満のパターン | 例 | PAWCARE への意味 |
|---|---|---|
| **N1 ログイン・機種変更・アップデートでデータが消えた** | 母子モ：再ログインで全データ消失、復元できず。11pets：更新でデータ移行が崩れた。MySOS：新しいアカウントでデータが見えない。Catlog：機種変更後のログイン不具合 | **ログインなし・端末内保存は強みになりうる**。ただし PAWCARE にも「Safariとホーム画面で保存先が別」「ブラウザ消去で消える」弱点がある → バックアップの声かけを続ける |
| **N2 AIの判定が当たらない・不安になる** | CatsMe：口内炎の猫が高得点（健康扱い）、注射後に低得点など結果が安定しない。Catlog：食べていないのに食事と記録（約7割の精度という声） | 判定しない方針（ADR-006）は不満の元を持たない。**取り入れない** |
| **N3 課金・自動更新・多頭の追加料金** | ペッツオーライ・CatsMe：無料期間後の自動課金、解約しにくい。11pets：無料は1匹だけ。Pawp：多頭は相談料が別 | 無料・登録なしは入口の強み。将来有料化するときは「多頭で値上げしない」が好まれる【仮説】 |
| **N4 リマインダーが現実とずれる** | PetDesk：済んだのに消せない、飲み忘れ後に日付が直らない、iCal への反映が不安定、完了履歴が「予定日」で残る | PAWCARE も .ics は一方通行（ADR-004）で同じ弱点。**完了は実際の時刻で記録し、終わりのある予定（処方の○日分）を作れるようにする**（取り入れ案 #4） |
| **N5 いざという時に使いにくい** | Q助：実際の緊急時には使いにくいという声、一方で文字の大きさ・コントラスト調整は好評 | 緊急画面は「押すところを少なく・大きく」を守る（取り入れ案 #9） |
| **N6 病院で見せにくい・印刷しにくい** | EPARKお薬手帳：病院で記録を見せたり印刷したりしにくい | PAWCARE は共有リンク・QR・印刷がある。**受付で見せる大きな表示**を足すとさらに強い（取り入れ案 #7） |
| **N7 回答の質がばらつく・本当に獣医師か不安** | ペッツオーライ：的外れな回答、本当に獣医師が答えているか疑問という声 | ADR-008 の相談は「外平先生が答える」と顔の見える形にする（6章） |

## 4. PAWCARE の差別化点と弱い点

### 4-1. 差別化点（今あるもの）

| # | 差別化点 | 根拠（調べた範囲） |
|---|---|---|
| D1 | **電話で読み上げるメモ**（ペット・症状・回数をそのまま読める短い文） | 27件の中に「電話で読み上げる文」を作るものは見つからなかった。人の医療でも Ubie・Ada は「受診時のまとめ」「医師向けレポート」で、電話向けではない |
| D2 | **30秒で読める受診用サマリーを、病院側の登録なしで渡せる**（リンク/QR・印刷） | ペット手帳・Animary・Ambii は**病院が契約した場合だけ**使える事前問診。PetDesk も病院側の導入が前提。11pets・CatsMe は「記録を見せる」まで。要点を先頭に並べ替えて渡すものはなかった |
| D3 | **判定しない**（病名・緊急度を出さず、連絡の目安と次の手順だけ） | 判定するもの（Ubie・Ada・Q助・CatsMe・Catlog AI）は「当たらない」「かえって不安」の不満を抱えやすい（N2）。獣医師法17条にも沿う |

| D5 | **もしもの準備（かかりつけ・夜間の電話、体重、バックアップ）＋誤食の疑い→すぐ連絡** | 平時の準備を促すのは Pet First Aid（米国）が近いが、日本の記録アプリには見当たらなかった |
| D6 | **ごはんチェック（RER・おやつ10%・AAFCO）と危険な食材の確認を、商品を勧めずに** | Catlog は活動量から食事量を提案（機器が必要）。商品を勧めない栄養の目安は他に見当たらなかった |
| D7 | **獣医師（外平先生）の監修とオンライン相談への橋渡し（ADR-008）** | ペット系の記録アプリで「特定の獣医師が監修し、その先生につながる」形は見当たらなかった。ただしまだ準備中 |

**取り入れない（法律・方針に反する）**

| 評価されている機能 | サービス | 取り入れない理由 | 置き換え |
|---|---|---|---|
| 症状から病名の候補を出す | Ubie・Ada | 飼い主に病名を示す＝獣医師法17条・ADR-006 | 獣医師だけが見る道具（concept v3 C1・C2、ADR-008） |
| 症状から緊急度を色で判定 | Q助 | 判定＝ADR-006。Q助は消防庁の救急プロトコルが根拠で、ペット版の公的な基準はない | 危険な兆候は「連絡する目安」の一覧のまま（監修済みのものだけ） |
| 写真AIで痛み・健康を点数化 | CatsMe | 判定＝ADR-006。精度の不満（N2）も大きい | 写真は「先生に見せる材料」として保存だけ（#10） |

| チョコ・殺鼠剤の摂取量計算 | ASPCA | 量から危険度を判断＝判定 | 量は記録して先生に伝える（#3） |
| 薬の効能・副作用の解説 | EPARKお薬手帳 | 動物の治療情報の提供は監修が前提 | 先生に言われたことを記録する欄（#4） |

### 5-2. 上位5件の実装仕様（テックリード向け）

共通ルール
- すべて `commit()` 経由で保存。新しい項目は `normalizeDb()` に既定値を足し、**古いバックアップを復元しても壊れない**ようにする（無い項目は空として扱う）
- 新しく出す文言で「大丈夫」「様子見でよい」「急がなくてよい」を使わない（concept v3 ルール2）。`tools/ai/guardrails.py` の禁止語チェックに通すことを推奨
- 「未入力」と「なし」を区別する（獣医師が「記録なし＝異常なし」と誤解しないため。concept v3 4章）
- E2E（tests/e2e.py）に各案のシナリオを1本ずつ足す

#### #1 もしもカード（ペット版メディカルID）

**基にした評価**：メディカルID（持病・アレルギー・薬・緊急連絡先をロック画面から見せられる）、Pet First Aid（★4.2・73件：プロフィールと救急病院検索が好評）、EPARKお薬手帳（★4.5・約22万件：オフライン閲覧が好評）。

**データ（追加）**
- `pet.conditions`：文字列 ≤300（持病・これまでの大きな病気・手術）
- `pet.conditionsNone`：真偽（「なし」を選んだ）
- `pet.allergies`：文字列 ≤200
- `pet.allergiesNone`：真偽
- `pet.meds`：配列 `[{ id, name ≤60, how ≤100（先生に言われた飲ませ方をそのまま）, from 'YYYY-MM-DD', to 'YYYY-MM-DD'|'' }]`（#4 の処方からも追加される）
- `pet.medsNone`：真偽
- `pet.microchip`：文字列（数字15桁のみ許可。任意）
- `pet.insurer` ≤60／`pet.policyNo` ≤40（任意。保険証の代わりに受付で見せられる）
- `db.settings.owner = { name ≤40, phone ≤20 }`、`db.settings.backup = { name ≤40, relation ≤20, phone ≤20 }`（飼い主に連絡がつかないときの連絡先）
- 既存の `pet.memo` は残す。カード編集画面の上に「今の補足メモ：○○（必要な部分を下の欄に移してください）」と表示するだけで、**自動で振り分けない**

**画面**
- ルート `#/card`（`VIEWS` に `card` を追加）。入口：①ホームのペット名カードの右に「🪪 もしもカード」ボタン ②緊急時画面の一番上（電話ボタンの直下）③設定
- 表示（大きめの文字・1画面に収める）：名前／種類・品種／年齢（生年月日）／性別・避妊去勢／体重（最後の体重記録の日付も「8.4kg（11/12）」）／持病／アレルギー／服用中の薬（`to` が今日以降または空のもの）／マイクロチップ／保険／かかりつけ（名前・📞）／夜間（名前・📞）／飼い主・予備の連絡先（📞）
  - 各項目は「未入力」（灰色）・「なし」・内容 の3通りで表示
  - 下に固定文：「飼い主が入力した情報です。獣医師の確認を受けたものではありません。」と作成日時
- ボタン（下部）
  1. 「編集」→ シートで上記の項目を入力。持病・アレルギー・薬は「なし」チェックボックスつき
  2. 「画像として保存」→ `<canvas>` に同じ内容を描いて PNG にする。`navigator.share({ files })` が使えれば共有シート（写真に保存・LINE）、使えなければダウンロード。説明：「写真アプリの『お気に入り』に入れておくと、オフラインでもすぐ出せます」
  3. 「印刷」→ `window.print()`。印刷用CSSでカード1枚（名刺〜はがき大）
  4. 「家族・預け先に送る」→ #5 の取り込みリンクと同じ仕組みで `#/card/<データ>` を作る（`encodePayload` を流用、`t:'card'`）。有効期間の目安：7日／30日。共有リンクと同じ注意文を表示
- 受け取った側：`#/card/...` を開くと閲覧専用のカード表示（電話ボタンは押せる）。下に「この端末のPAWCAREに取り込む」（#5 の取り込み処理でプロフィールだけ追加）

**動き**
- 「もしもの準備」チェックリストに「もしもカード（持病・アレルギー・薬を『内容』または『なし』で埋める）」を追加。3つとも未入力でなければ完了
- 共有シート（病院向け）の「プロフィールの補足メモを含める」を「もしもカードの内容（持病・アレルギー・服用中の薬）を含める」に置き換え、受診用サマリーの要点に3行で出す
- 電話読み上げメモ（`phoneScript`）の「持病・メモ」行を、`conditions`／`allergies`／`meds` から作る（「持病は○○、アレルギーはなし、飲んでいる薬は○○です。」）。未入力の項目は読まない
- オフラインで開ける（Service Worker のキャッシュ対象。`sw.js` の CACHE 名を上げる）

#### #2 前回から○時間・今日の回数

**基にした評価**：ぴよログ（★4.8・約12万件：各項目の最後が何時間前か分かりやすいという声、1日の自動集計）、Huckleberry（★4.9・約7.9万件：記録で医師の質問に答えやすいという声）。

**データ**：追加なし（`db.logs` から計算）

**画面（ホームの「ワンタップで記録」）**
- 各ボタンのラベルの下に小さく2行目を出す：`今日 3回・最後 40分前`
  - 今日0回で過去7日に記録あり：`今日 0回・最後 2日前`
  - 7日以内に記録なし：`—`
  - 体重ボタン：`最後 8.4kg（5日前）`
- 時間の表記：60分未満「○分前」、24時間未満「○時間前」、それ以上「○日前」
- ボタンを押すと記録する動きは今のまま（2行目は押しても何も起きない）
- ホーム表示中は60秒ごとに2行目だけ更新（`setInterval`。画面を離れたら `clearInterval`）
- 色は全ボタン同じ。**「○時間おしっこが出ていない」などの注意・色分けは出さない**（判定になる。必要なら外平先生の監修案件として別に検討）

**他の画面への反映**
- 電話読み上げメモ：24時間以内に記録がある `ingest`／`vomit`／`regurgitate`／`stool`／`urine` について「最後の嘔吐は今日10時40分（約1時間前）です。」を回数の文の後に1行ずつ足す
- 受診用サマリーの要点：「記録の回数（24時間）」の行に、各項目の最後の時刻を括弧で（例「嘔吐 3回（最後 11/18 10:40）」）
- 問診の「頻度」ステップ：選択肢の上に「記録では今日 嘔吐3回（最後 10:40）」を参考表示。選択は飼い主がする（自動入力しない）

#### #3 誤食メモの項目化と「確認→記録→電話」のひと続き

**基にした評価**：ASPCA Animal Poison（有害物の検索、オフライン、中毒相談へのワンタッチ電話）、Pet First Aid（有害物の見分け方）、Q助（結果からそのまま電話・検索に進める）。

**データ（追加）**：`category === 'ingest'` の記録に `log.ingest` を持たせる
```
log.ingest = {
  what: '' ≤100,          // 何を（例：ぶどう、保冷剤、薬のシート）
  product: '' ≤100,       // 商品名・成分表示（分かれば）
  amount: ''|'little'|'half'|'all'|'unknown',  // ひとかけら・少し／半分くらい／全部／分からない
  amountNote: '' ≤50,     // 例：「3粒」「1/4枚」
  when: ''|'now'|'30m'|'1h'|'time'|'unknown',  // たった今／30分以内／1時間以内／時刻を入力／分からない
  ateAt: 'YYYY-MM-DDTHH:mm'|'',  // when==='time' のとき
  packageKept: false      // 包装・残りを手元に置いた
}
```
共有リンクの記録配列は今 `[datetime, category, value, memo]` なので、`ingest` は `memo` の先頭に「何を：…／量：…／時刻：…」の形で文字にして入れる（共有の形式は変えない）。

**画面**
- ワンタップの「誤食の疑い」を押したあとのシート（今の `openSheet('誤食の疑いを記録しました', …)`）を次の順に組み直す
  1. 赤い注意（今の文のまま）
  2. 電話ボタン：かかりつけ（登録時）・夜間（登録時）・「緊急時の案内を開く」。**入力欄より上**に置く（命の安全が先：concept v3 ルール1）
  3. 見出し「電話の前に、分かる範囲で（あとからでも入力できます）」の下に、上の項目の入力欄。`amount`・`when` は大きめのボタンで選ぶ
  4. 「保存」→ 保存後、同じシートに「電話で読み上げるメモ」を表示（下の文）＋「コピー」
- `what`／`product` を入力したら、その場で既存の危険な食材チェック（`NU.toxic` のキーワード照合）を走らせ、当たれば「PAWCAREの一覧では『ぶどう・レーズン』に当たります。」と表示。当たらない場合も含め、必ず「一覧にないものでも安全という意味ではありません。病院に連絡してください。」を出す
- ごはんチェックの「危険な食材の確認」で当たったとき、結果の下に「食べてしまった → 誤食として記録して電話する」ボタンを出す。押すと `ingest` の記録を作り（`what` に入力した語を入れる）、上のシートを開く

**電話読み上げメモへの反映**（24時間以内の `ingest` 記録があるとき、先頭に）
「○時ごろ（約○分前）、［what］（［product］）を［量］食べた可能性があります。包装は手元にあります。」 未入力の部分は省く。

**しないこと**：量や体重から危険度を計算しない／「少量なら問題ない」などを書かない／吐かせ方など家での処置を書かない（concept v3 1-3）。

#### #4 受診記録と、処方からの服薬予定

**基にした評価**：アニカル（★4.4・4,162件：請求の履歴が通院記録の代わりになるという声）、EPARKお薬手帳（★4.5・約22万件：家族の管理・服薬アラーム）、Medisafe（★4.7・約10.2万件：医師向けPDFレポート）、PetDesk（★4.9・約51.3万件。**不満**：済んだ予定が消せない、完了が予定日で残る）。

**データ（追加）**：`db.visits`（バックアップ・復元・CSV書き出しの対象に加える。ペット削除時は一緒に削除）
```
{ id, petId,
  date: 'YYYY-MM-DD',
  hospital: 'regular'|'night'|'other', hospitalName: '' ≤60,
  reason: '' ≤200,        // 受診した理由（飼い主の言葉）
  vetSaid: '' ≤1000,      // 先生に言われたこと（聞いたとおりに）
  meds: [{ id, name ≤60, how ≤100, days: number|'' }],   // 処方された薬
  nextDate: 'YYYY-MM-DD'|'',   // 次に来るよう言われた日
  cost: number|'',        // 支払った金額（任意。保険請求の控え）
  createdAt, updatedAt }
```
`db.reminders` に `endAt: 'YYYY-MM-DD'|''` を追加（くり返しの終わりの日）。

**画面**
- ルート `#/visits`。入口：ホームの「体調が気になるとき」カードの下に「🏥 受診の記録」カード、予定一覧、設定
- 一覧：新しい順。「11/10 かかりつけ（○○動物病院）— 嘔吐」。タップで詳細・編集
- 追加フォーム：日付（既定：今日）／病院（かかりつけ・夜間は登録済みの名前を選択、その他は入力）／受診の理由／先生に言われたこと（プレースホルダー：「例：○日分の薬を1日2回。吐いたら電話」）／処方された薬（「＋薬を追加」で行を増やす：名前・飲ませ方・日数）／次回の日付／金額
- 文言：フォームの上に「先生から聞いたことを、聞いたとおりに残すメモです。分からないことは病院に確認してください。」

**動き**
- 薬の行ごとに「服薬の予定を作る」ボタン → 既存の予定フォームを開き、種類=服薬、タイトル=薬の名前、メモ=飲ませ方、くり返し=毎日、**終わりの日=受診日＋日数−1** を入れた状態にする。**時刻は空欄で、飼い主が入れる**（アプリが飲ませる時刻・回数を決めない）。1日2回なら飼い主が2件作る（フォームに「1日に複数回のときは、時刻ごとに作ってください」）
- 終わりの日を過ぎたくり返し予定は、完了時に次回へ進めず「完了済み」へ。.ics の RRULE に `UNTIL` を付ける
- 予定の「完了」は**押した実際の時刻**で健康記録に「服薬」を追加（今の動き。PetDesk の不満を踏まえ、変えないことを明記してテスト化）
- 薬に日数があり受診日から期間内なら、もしもカードの「服用中の薬」に自動で出す（「受診記録から」と小さく表示）
- `nextDate` があれば「予定を作る」ボタン（種類=健康診断・通院、日付=nextDate、時刻は空）
- 種類「健康診断・通院」の予定を完了したとき、トーストに「受診の記録をつける」ボタン
- 病院向け共有シートに「前回の受診（30日以内）を含める」チェック（既定：オン）。受診用サマリーの要点の下に「前回の受診：11/10 ○○動物病院／理由：嘔吐／先生に言われたこと：…／処方：○○ 7日分」と出す（飼い主の記録である旨の注記つき）。夜間の別病院で役立つ

**しないこと**：薬の効能・副作用・量の目安を載せない／薬の名前から何かを判断しない。

#### #5 家族・預け先への引き継ぎ（テキスト＋取り込みリンク）

**基にした評価**：ぴよログ（★4.8：夫婦でリアルタイム共有が好評）、Huckleberry（★4.9：共有で世話の受け渡しがスムーズ）、ペットノートPlus（★4.6：最大15人で共有）、Medisafe（家族の管理）。PAWCARE はサーバーがない（ADR-003）ので、**「同期」ではなく「手で送る」**形にする。

**画面**
- ホームの「今日の記録」カードの見出し右に「👪 引き継ぐ」ボタン
- シートの項目
  - 期間：今日／直近24時間／直近3日（既定：直近24時間）
  - 含めるもの（チェック）：記録の回数と最後の時刻（#2 と同じ表記）／これから24時間の予定（服薬など）／もしもカードのリンク／記録を相手のPAWCAREに取り込むリンク
  - 「伝えたいこと」自由記述 ≤300（例：夜もう一度吐いたら○○病院に電話して）
- 「作る」→ テキストを表示：
  ```
  【こむぎの引き継ぎ 11/18 18:00】
  ・嘔吐 2回（最後 15:20）・ごはん 1回（最後 8:00、半分）・排尿 3回（最後 17:10）
  ・これからの予定：19:00 服薬（○○）
  ・伝えたいこと：夜もう一度吐いたら○○病院（03-xxxx）に電話して
  ・取り込みリンク：https://…#/import/…
  ```
  ボタン：「コピー」「LINE・メールで送る」（`navigator.share`）

**取り込みリンク `#/import/<データ>`**
- 中身：`{ v:1, t:'handoff', c: 作成日時, x: 期限(3日), from: 送り主の表示名(任意), pet: { id, name, species, breed, birthday, sex, weight, conditions, allergies, meds… }, logs: [ {id, datetime, category, value, memo, ingest} ] }`。`encodePayload` を流用、記録は最大120件・メモ200文字（共有リンクと同じ上限）
- 開いた側の表示：「○○さんから：こむぎの記録 12件（11/17 08:00〜11/18 17:10）」と記録の一覧（閲覧のみ）
- ボタン「この端末のPAWCAREに取り込む」
  - 同じ `pet.id` がある → そのペットに記録を追加
  - ない → 「新しいペットとして追加」または「既存のペットに取り込む（選択）」
  - **同じ `log.id` は追加しない。既存の記録は消さない・上書きしない**（片方向の追加だけ）
  - 取り込んだ記録に `importBatch: <id>` を付け、結果を「12件追加・3件はすでにありました」と表示。直後のトーストに「取り消す」（同じ `importBatch` の記録を削除）
- 画面の注意（共有リンクと同じ文）：リンクを知っている人は誰でも読める／取り消せない／自動では同期されない（相手が記録したものは、相手から引き継ぎを送ってもらう）

**しないこと**：自動同期と誤解される表現（「共有中」「同期」）を使わない。病院向け共有リンク（`#/view/`）と画面・色を分け、病院用と家族用を取り違えないようにする。

## 6. 見直しが必要な決定と、その理由

今回のトップ5はどの決定も変えずに作れる。ただし調査から、次の2点は**次の検証のあとで見直す材料**がある。

| 決定 | 見直しの材料 | 提案 |
|---|---|---|
| **ADR-003 クラウド同期・ログインは見送り** | 評価の高い記録アプリはほぼすべて家族共有を持ち、レビューでも最もほめられている（ぴよログ・Huckleberry・ペットノートPlus・母子モ・EPARK）。一方、ログイン型はデータ消失の不満が目立つ（母子モ・11pets・MySOS・Catlog） | **今は変えない。** #5（手で送る引き継ぎ）でどこまで足りるかを4週間の検証で見る。アンケートに「家族と共有できないことが不便だった（はい／いいえ）」を足し、多ければ再検討（README「将来のクラウド化の提案」を出発点に） |
| **ADR-004 通知はカレンダー任せ／ADR-008 オンライン相談の試作** | 時間外に専門家へつながる安心は、ペットのサービスで最も評価が高い（Airvet ★4.9・約1.1万件、Pawp ★4.9・約1.5万件、ペットドクターのレビュー）。外平先生との相談をアプリ内でやり取りするには、メッセージの保管・通知にサーバーが要る | **ADR-008 を進めるとき、ADR-003・004 の見直しが必要**になる。それまでは「相談はLINE等の外部の窓口で受け、PAWCAREは送る文（問診メモ・サマリーのリンク）を作るだけ」にすればサーバーなしで試せる【仮説：外平先生の運用と、相談の範囲（健康相談か診療か）は ADR-008 の未確認事項のまま】 |

「特定商品のおすすめはしない」「診断しない」の決定には、変える材料はなかった（むしろ判定するサービスに不満が集まっている：3-2 N2）。
