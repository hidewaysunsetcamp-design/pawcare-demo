# ことぽすとチーム

発足：2026-11-20
目的：**うちの子の“いつも”を、先生へ。** — 記録が続き、病院に正確に伝わり、いざという時に迷わないサービスを、飼い主・ペット・獣医師の立場で作る。

## メンバー（`.claude/agents/`）
| 担当 | 呼び名 | 主な仕事 | 成果物の置き場所 |
|---|---|---|---|
| まとめ役（指揮・実装） | Claude（クラウド側／Claude Code） | 仕事の割り振り、決定、実装、テスト、公開 | コード・`docs/DECISIONS.md` |
| 制作 | production-director | 画面・動き・音・振動・絵の設計とレビュー | `docs/design/` |
| 開発 | dev-engineer | 実装、調整値の分離、テスト、チケット整理 | コード・`docs/tasks/` |
| 広報 | pr-planner | 紹介ページ・SNS・動画・クラファン・実演 | `docs/pr/` |
| 分析 | analyst | 目的に合っているかの評価、優先度づけ | `docs/review/` |
| コンセプト | concept-planner | 事業・製品の方向づけ | `docs/concept/` |
| 市場・競合 | market-analyst | 類似サービスの調査 | `docs/research/` |

全員が `CLAUDE.md` の「必ず守ること」と `docs/team/work-attitude.md`（仕事の姿勢）に従う。提案は一択で出し、理由と注意点を添える。

## 動き方
1. オーナーが「やりたいこと」を伝える → まとめ役が担当に割り振る（同時に動かせるものは同時に）。
2. 各担当は成果物をファイルに残す（会話の中だけで終わらせない）。担当どうしは直接やりとりせず、まとめ役がすり合わせて一つに決める。
3. 決めたことは ADR に、やることは `docs/tasks/` に、経過は Notion の開発ログに残す。
4. 画面を変えたら必ずテスト（`tests/verify.sh`・`tests/e2e.py`）を全件合格させてから公開。
5. 課金・大きな仕様変更・外部への送信は、オーナーに確認してから。
